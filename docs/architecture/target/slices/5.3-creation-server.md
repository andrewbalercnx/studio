# Slice 5.3 — Story creation on the server

> **Created**: 2026-10-29 · Phase 5, slice 2 (first half) of `../../REVIEW_PLAN.md`.
> Branch `rebuild/phase5-creation-server`, stacked on 5.1 (#13) and 5.2 (#14).

The server side of [`../creation.md`](../creation.md): one Story (ADR-0004), five creation modes
behind one interface (ADR-0009), the creation routes and the `story.finish` job. **No client uses it
yet**: slice 5.4 moves web, kids PWA and mobile onto it, deletes the old modes, routes and flows,
and resets trial data with `scripts/reset-trial-data.mjs`. Nothing old is changed or deleted here.

## CreationMode mapping (no collection renamed yet)

**CreationMode ← `storyGenerators/{sourceId}`**

| `modeId` | Document | Prompt keys read (default = today's flow default) |
|----------|----------|--------------------------------------------------|
| `wizard` | `wizard` | `questionGeneration`, `storyGeneration` |
| `freeplay` | `gemini3` | `systemPrompt` |
| `guided` | `gemini4` | `systemPrompt`, `phase_opening` … `phase_development` |
| `friends` | `friends` | `characterProposal`, `scenarioGeneration`, `synopsisGeneration`, `storyGeneration` |
| `adventure` | `beat` | none: prompts come from the chosen `storyTypes/{id}.promptConfig` |

| CreationMode field | From |
|--------------------|------|
| `status` | `status` (`live` / `draft` / `archived`); only `live` can be started (admins and writers may use drafts) |
| `enabledForKids` | `enabledForKids === true` — required when a child persona is active (403 `MODE_NOT_FOR_KIDS`). Today's seed gives `beat` none, so `adventure` is parent-only until the flag is set |
| `model` | `model` (target) else `defaultModel`: the `creation.text` override (ADR-0008). Per-prompt `promptConfig[key].model` is **not** honoured |
| `temperature`, `promptTemperatures` | `defaultTemperature`, `promptConfig[key].temperature` |
| `presentation` | Through `presentGeneratorsForKids` (jargon scrubbed): name, description, icon, gradients, loading message, order, one `recommended` |

Curated prompts still say "use `$$id$$` placeholders"; `toCastTokenPrompt` rewrites every `$$x$$`
in them to `[[cast:x]]` (so `$$CHILD_ID_PLACEHOLDER$$` and `$$childId$$` become the hero's token).
The instruction's intent is unchanged.

**StoryType ← `storyTypes/{id}`**: `name`, `shortDescription`, `status`, `ageFrom`/`ageTo`,
`arcTemplate.steps` (string steps normalised as today), `promptConfig` (role, rules, style, themes,
beat and ending instructions; `model.temperature` and `model.maxOutputTokens` honoured,
`model.name` not — ADR-0008).

## How each mode was ported

| Mode | Today | Here | Not ported faithfully |
|------|-------|------|-----------------------|
| `wizard` | `storyWizardFlow`: 4 questions (2–4 choices), then the story; flow writes `stories/{sid}`; compile skipped | Same prompts, temperatures (0.8 / 0.7), `MAX_QUESTIONS = 4`, model title kept as `titleHint`; answers in `modeState.answers` (the kids PWA kept them only in React state) | Nothing of substance; ends through `story.finish` (gets a synopsis and is charged, which today it was not) |
| `freeplay` | `gemini3Flow`: one prompt with the conversation as text, "story temperature" over 15 exchanges, model decides when complete | Same template variables, guidance thresholds (0.4 / 0.6 / 0.8), temperature 0.9, 8000 tokens; history from turns; options may introduce characters | `debug` output not returned |
| `guided` | `gemini4Flow` via `aiBeta.chat`: phases by question count, 6 or 8 questions by age, A–C + M | Same prompts and phases; `generate` with the system prompt and the same history as chat messages (the opening request kept as the first user message); M sends today's "Tell me more…" message; `existingCharacterId` adds that family member to the cast | Chat API replaced by an equivalent messages call |
| `friends` | `friendsFlow`: propose characters → confirm → scenarios → synopses (+ more) → story; flow writes `stories/{sid}`; compile skipped | Same four prompts and temperatures; proposal is a `castPick` turn (`preselected` options; setup `castIds` preselected too); `more` is an option id; title kept as `titleHint` | Per-prompt models (ADR-0008); "change characters" after confirming is not offered (today's UI did not either) |
| `adventure` | `storyBeatFlow` + client-side `arcStepIndex` + `endingFlow` + `storyTextCompileFlow` | Story type chosen as the first turn (or `storyTypeId` at create); beats from `promptConfig` with today's sections (objective, role, subject, narrative, current beat, newly introduced characters, world state, scene annotation), 8-message window + summary of earlier beats; after the last arc step, three endings; the chosen ending is polished with the compile prompt into one text | `levelBandOverrides` (no client ever set a level band); the legacy `promptConfigs` fallback (a StoryType without `promptConfig` uses the shared storyteller message); a StoryType without arc steps ends after 6 beats (today it never ended); the polish **keeps cast tokens** instead of writing names (names written anyway are tokenised back); the compile synopsis (made by `story.finish`); flash `thinkingBudget: 0` |

Common to every mode:

- **Characters the AI introduces** (option `introducesCharacter`): the profile is generated as
  `generateCharacterProfile` did (failure → today's defaults), the character is created in
  `characters` with `origin: 'story'`, `originStoryId`, `ownerParentUid`, `childId` = the hero,
  `isParentGenerated: false`, `usageCount: 1`, `photos: []` and **no avatar** (today: a picsum
  placeholder; ADR-0006), and joins the cast in the transaction that records the turn. Today the
  browser created it through `/api/characters/create` and fired avatar generation; avatars for these
  characters wait for the Characters slice.
- **Title and synopsis**: `story.finish` ports compile's `generateSynopsis` (on the text with names)
  and `storyTitleFlow` (from the synopsis); a mode's title hint wins.
- **Models**: conversation calls (every engine turn, adventure's polish) are `creation.text`
  (default `gemini-3.8-flash`; Gemini 2.5 was retired in October 2026; a mode's `defaultModel`
  overrides it, so set adventure's to Flash to match today's beat engine). Title and synopsis are
  their own purpose, `story.finish` (default `gemini-3.8-flash`), and ignore the mode's
  model.
- **Not ported** (owned elsewhere or retired): session events, `aiRunTraces`, character usage
  counts, the story group avatar and whole-story audio that compile started with `after()` (the Book
  pipeline narrates pages), the character-traits Q&A of the retired warmup engine.

## Decisions where the docs were silent

| Topic | Decision |
|-------|----------|
| Field names | `modeId` (the foundations schema had `mode`), plus `schemaVersion: 2` so rules and `story-source.ts` tell target Stories from legacy ones in the shared `stories` collection |
| `castId` | The child's or character's document id (one person appears once), so `[[cast:id]]` tokens resolve with no lookup table and the Book pipeline's cast loader reads them unchanged |
| Final cast | On `done` the cast becomes the hero plus everyone the final text names (family members named for the first time join with `addedBy: 'ai'`); people picked or introduced but not in the text drop out, so Books draw only who is in the story |
| Engine state | `Story.modeState` (engines mutate `ctx.modeState`; the service stores it with the turn). The interface stays `start` / `respond` |
| Turn additions | `expects` (`choice` / `text` / `castPick`) and option `preselected` (castPick) as UI hints; `promptDisplay` and option `display` store the words with names, so clients render without lookups (server-first) |
| `NewCastMember` | `{ kind: 'existing', castId, ref, addedBy }` or `{ kind: 'new', castId, character, addedBy: 'ai' }`; existing ones must be in the owner-scoped roster |
| Story id | `st_` + hash(ownerUid, idempotencyKey); the key is required. A repeat returns the Story and first turn; another child or mode with the same key → 409 |
| AI character id | `chr_` + hash(storyId, turn index, name): a retried turn creates the same document, never two |
| Turn concurrency | Claim in a transaction (`pendingTurn { idempotencyKey, leaseUntil }`, 4-minute lease), model calls outside any transaction, commit in a second transaction that checks the claim. Same key repeated after commit → the recorded reply (200); while running → 409 `TURN_IN_PROGRESS`; another key → 409 `TURN_CONFLICT`. An expired lease (crashed request) is taken over |
| Model failure | 503 `AI_UNAVAILABLE` / `AI_BAD_OUTPUT` (new `ServiceUnavailableError`); nothing recorded, claim released, the same request can be repeated |
| Tokens from the model | Every form (`[[cast:id]]`, `$$id$$`, `$id$`, `$$Name$$`, `$$childId$$`) is resolved against the roster; an unknown name is kept as words, an unknown id becomes "a friend" — never another family's id |
| Adventure story type | Asked as the first turn (live types for the child's age, by name), or given as `storyTypeId` at create; stored on `Story.storyTypeId` |
| Kids check | "Enabled for that child" = `enabledForKids` when a valid child-persona cookie is present (the persona model has no per-child mode list) |
| Allowance | Checked at create (402 before any model call or write); consumed once in the transaction that sets `complete` (`allowance { charged, remaining, reason }` recorded). If the family ran out in between, the Story still completes with `charged: false` (today's compile: a finished story is never failed by the ledger) |
| `story.finish` | Queue `ai-text`, 3 attempts; job key `story.finish:{storyId}` (a retry run adds `:run-N`). The final attempt or a permanent error sets `failed` + `error`; `POST /api/stories/{id}/finish` (a fourth route) moves `failed` → `finishing` with a new job |
| Abandon | Only from `creating`; idempotent; clears the claim |
| TEST_MODE | Every model call site carries a deterministic fixture returned when `isTestMode()` (the engines' state machines still run): wizard 4 questions, freeplay and guided finish on their third model call (each offers a character-introducing option), friends 3 scenarios / synopses, adventure beats per arc step + 3 endings; `story.finish` writes "{hero}'s Story" / "{hero} has a wonderful adventure." |
| Rules | Owner reads a target Story and its turns (`ownerUid`; lists filter on it); no client writes. Legacy stories keep rename / art style / soft delete and storybook acknowledgement, and cannot be turned into target Stories |
| Book input | `story-source.ts` reads both shapes; a target Story makes Books only when `complete` (409 `STORY_NOT_READY` otherwise) |

## Reset script (`scripts/reset-trial-data.mjs`)

Dry run by default (documents per collection, with and without subcollections). Deleting needs
`--confirm --project <id>` where the id equals the credentials' project, and the config export
(`seed/config/_manifest.json`, or `--export-dir`) unless `--skip-export-check`.

- **Deletes** (with all subcollections): `storySessions`, `children/*/sessions`, `stories`,
  `storyBooks`, `printStoryBooks`, `manuscripts`, `books`, `jobs`, `shareLinks`.
- **Keeps**: `users`, `children`, `characters` (including story-introduced ones), every config
  collection, `aiFlowLogs`, `aiRunTraces`, `devTodos`, `tickets`, `feedback`.
- **Allowances kept by default** (`--reset-allowances` deletes `entitlementLedgers`): ledgers hold
  purchases and grants, not trial content. **Print orders kept** unless `--include-orders` (records
  tied to Mixam and money).
- `--storage [--bucket]` deletes the deleted documents' Storage prefixes; children's and
  characters' files stay.
- Batches of 400 with exponential backoff; summary line at the end. Runbook: `docs/DEPLOYMENT.md` §10.

## Known gaps (slice 5.4 and later)

- Clients (web, kids PWA, mobile, `packages/api-client`) still use the old modes; 5.4 switches them,
  deletes the mode-specific routes, flows, `storySessions` code and the legacy `story-source` branch,
  ports the E2E funnel to the new routes (TEST_MODE fixtures are ready) and runs the reset.
- `GET /api/kids-generators` still serves the chooser; `listCreationModes` is ready to replace it.
- Avatars for story-introduced characters, character usage counts: Characters slice.
- No GET routes: clients read `stories/{id}` and `turns` directly (owner-read rules).
