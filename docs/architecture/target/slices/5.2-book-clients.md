# Slice 5.2 — Clients on the Book pipeline

> **Created**: 2026-10-29 · Phase 5, slice 1 (second half) of `../../REVIEW_PLAN.md`.
> Branch `rebuild/phase5-book-clients`, stacked on 5.1 (#13) and Phase 4 (#12).

The web app and the kids PWA make and read Books on the server pipeline from
[`5.1-book-server.md`](5.1-book-server.md); the old `storybookV2` generation code is deleted in the
same change (rebuild-and-delete, trial data not migrated).

## What the clients do now

```
story complete ─▶ BookChooser: Form (storyOutputTypes) then Style (imageStyles)
               ─▶ POST /api/books { storyId, formId, styleId, idempotencyKey }
               ─▶ /kids/book/{bookId} (PWA) | /books/{bookId} (web)
                    listeners on books/{id}, books/{id}/pages, manuscripts/{id}, manuscripts/{id}/pages
                    progress (status, art {total, done, failed}, manuscript status) → reader
```

| Piece | Where |
|-------|-------|
| Client types and route calls (create, retry, lock, unlock; one key per choice) | `src/lib/books/` |
| Read-only listeners (`useBook`, `useBookPages`, `useBookPage`, `useManuscript`, `useManuscriptPages`, `useBooks`) and `useCreateBook` | `src/hooks/use-books.ts` |
| Chooser, progress, reader, list card, book view with parent controls | `src/components/books/` |
| Web book page (progress, reader; parent: retry, lock/unlock, "Printing is coming soon") | `src/app/books/[bookId]` |
| Kids PWA book page (no parent controls) | `src/app/kids/book/[bookId]` |
| Create entry points | `kids/create/[sessionId]/style`, `child/[childId]/create-book/[storyId]`, the dialog on `story/[storyId]` |
| Lists on server status | kids `My Books`, child `My Books` and dashboard count, `story/[storyId]`, `parent/storybooks/[childId]` |

- **Idempotency**: `useCreateBook` keeps one `crypto.randomUUID()` per (story, Form, Style) in a ref,
  so a double tap or a retry after a network error repeats it; the server returns the same Book and
  charges once. A different choice gets a new key.
- **Reads**: list queries filter on `ownerUid == uid` (the owner-read rules require it for lists);
  hooks wait for auth before subscribing (a denied read ends a listener). Pages are sorted by
  `pageNumber` in the hook and Books by `createdAt` (no composite indexes needed).
- **Status**: the clients show `book.status` as the job runner writes it. `ready`, `partial` and
  `locked` open the reader; `illustrating` shows progress; `failed` says the book got stuck. Nothing
  is derived from pages on the client (the three readiness rules of `as-is/areas/clients.md` §2c.5
  are gone).
- **Parent mode**: `/books/{id}` shows retry (on failed pages) and lock/unlock when `roleMode` is
  parent or admin; every action asks for the PIN through `useParentGuard` first. The kids PWA has no
  parent controls.
- **Print**: not offered for Books. The book page says "Printing is coming soon"; the parent list
  says so above the Books. The print slice adds layouts, renders and orders.

## Old storybooks (choice)

Shown **read-only to parents only**, where they appear today: the "Earlier storybooks" section of
`/story/{storyId}`, `/parent/storybooks/{childId}` (with its print button), `/storybook/{id}` (pages,
print layout and order, share for already-locked books) and `/storybook/{id}/read`. Generating,
repainting, page edits, finalize/unlock and narration for them are removed. **Child-facing lists
(kids PWA, web child shell) show new Books only**: merging both models into the child lists would
keep the client-side readiness rules alive for data that is about to be reset.

## Mobile

Book creation is switched off: the story screen says "Make books in the web app for now"; the
create-book and generating screens and the client methods that called `storybookV2` are deleted.
The app still lists and reads old storybooks; it does not show new Books yet. `packages/api-client`
drops `createStorybook`, `generatePages`, `generateImages` and the `getStorybookStatus` stub and
adds `createBook` (POST `/api/books` with an idempotency key). No APK build.

## System test

`POST /api/internal/system-test` (daily, live models) now creates a Book through the same service
and runs only `manuscript.paginate`, the cast sheet and the cover's `book.pageArt` in process, then
checks scene tags, location keys and the cover picture, and cleans up.

## E2E

The blocking funnel goes story complete → Form + Style → `POST /api/books` → TEST_MODE pipeline on
the e2e server's in-process dispatcher (`JOBS_DISPATCHER=in-process` forced by
`scripts/start-e2e-server.mjs`) → reader shows the cover and a page → My Books shows the Book as
ready. See `docs/testing/e2e.md`.

## Known gaps

- Print for Books (layouts, renders, orders, share links) — print slice.
- Page text editing for Books (today's `pageEdit` is gone with the old pipeline).
- Mobile reads only old storybooks; Books in the app wait for the clients phase.
- The story readers and `/stories` still read `stories` directly (creation slice).
