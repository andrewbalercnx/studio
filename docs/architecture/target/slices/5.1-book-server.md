## Input: today's story as the Story

The creation slice comes later, so the input is `stories/{storyId}` as written today:

| Story (target) | `stories/{storyId}` (today) |
|----------------|-----------------------------|
| `ownerUid` | `parentUid` |
| `childId` | `childId` |
| `text` (cast tokens) | `storyText` (`$$id$$`; the AI fallback `$id$`; `[[cast:id]]` also parsed) |
| `title` | `metadata.title` |
| `synopsis` | `synopsis` |
| `cast[]` | `childId` (hero) + `actors[]` + any other token in the text, each resolved to the owner's `children` or `characters` doc (`castId` = doc id, `role` hero/supporting, `addedBy: setup`). Ids outside the family are dropped; legacy name tokens are matched by `displayName` inside the family only |

It is read through its own permissive schema (`story-source.ts`), not the `stories` repository,
whose target schema legacy documents do not match.

## Catalogue mapping (no collection renamed yet)

**Form ← `storyOutputTypes/{formId}`**

| Form | From |
|------|------|
| `category` | `category` (default `picture_book`) |
| `allowedLengths` | `picture_book`: **12, 16, 24** (ADR-0011). Others: `[layoutHints.pageCount]`, else a category default (poem 8, coloring_pages 12, audio_script 6) |
| `defaultLength` | The allowed length nearest `layoutHints.pageCount` (picture books default 16 when unset) |
| `densities` | `picture-led`, `balanced`, `text-led` |
| `defaultDensity` | `layoutHints.textDensity`: `very_low` → `picture-led`, `low` → `balanced`, `medium` → `text-led`; default `balanced` |
| `readingLevel` | `ageRange`, else `all` |
| `paginationPrompt`, `styleHint`, `rhymes` | `paginationPrompt`, `aiHints.style`, `aiHints.allowRhyme` |
| `status` | `status`; only `live` Forms can be chosen (admins and writers may use drafts) |

Target-shape fields (`allowedLengths`, `defaultLength`, `densities`, `defaultDensity`,
`readingLevel`) win when a document already has them, so re-seeded `forms` read the same way.

**Style ← `imageStyles/{styleId}`**: `stylePrompt` → `prompt` (required), `title` → `name`,
`exampleImages[].url`, `sampleImageUrl`, `sceneExemplars[tag].imageUrl` where `status == 'ready'`
→ `sceneReferences[tag]`. Reference order for page art (as today): the scene reference for the
page's tag, else the example images, else the sample. Cast sheets use example images, else the
sample.

**Layout ← `printLayouts/{layoutId}`** (only what Book creation needs): `name`, `medium = print`,
page aspect from `leafWidth / leafHeight`, page rules from `pageConstraints` or the linked
`printProducts.mixamSpec` (`resolvePageConstraints`). A Layout supports a length when story pages +
3 (title, dedication, end), padded to the page multiple and minimum, fit under `maxPages` (12 and
16 → 24, 24 → 28 for case binding, ADR-0011). Optional target fields `supportedLengths` /
`supportedDensities` are honoured. A screen Book has `layoutId: null` and square art.

## Pipeline

```
manuscript.paginate (ai-text) ─ ready ─┬─▶ manuscript.narrate × length (tts)
                                       └─▶ book.prepareCast for each Book waiting (status illustrating)
book.prepareCast (render, coordinator) ─▶ book.castSheet × cast (ai-image)
   fan-in ─▶ book.illustrate (render, coordinator, run "initial")
book.illustrate ─▶ book.pageArt × pages without art (ai-image)
   fan-in ─▶ pages' artJob + Book.art rollup; status ready | partial | failed
retry route ─▶ book.illustrate (run "retry-<uuid>", pages [n])
```

- **Why coordinators**: the runner's fan-in (`onChildrenComplete`) is the only race-free way to act
  once when the last of several jobs ends. `book.prepareCast` and `book.illustrate` are added to
  `JOB_KINDS` for that; they do no AI work.
- **Rollup** is always recomputed from the Book's pages (art present → done; latest job failed or
  cancelled → failed; otherwise pending), so concurrent runs (a retry while another finishes)
  converge. Status: pending > 0 → `illustrating`; no failures → `ready`; nothing drawn → `failed`;
  else `partial`.
- **Book creation** in one transaction: read the Book (idempotency key), the Manuscript, the
  ledger; charge one `storybook_allowance`; enqueue jobs; write ledger, Manuscript (if new), Book
  and its pages. If the Manuscript is `ready`, `book.prepareCast` is enqueued in that transaction;
  if not, pagination enqueues it when it commits `ready`. Either the Book sees `ready`, or
  pagination's post-commit query sees the Book, so no Book is missed (and both paths produce the
  same job id).
- **Manuscript failure**: on the final attempt (or a non-retryable error) pagination marks the
  Manuscript `failed` and every Book waiting on it `failed`. `POST /api/manuscripts` (or
  `POST /api/books` with `storyId + formId`) paginates a failed Manuscript again with a new job.
- **Narration** never blocks art; a page without text gets no clip.
- **Idempotent handlers**: pagination skips to its follow-on jobs when the Manuscript is already
  `ready`; narration, cast sheets and page art stop when their output exists.

## Decisions where the target docs were silent

| Topic | Decision |
|-------|----------|
| Manuscript id | `ms_` + hash(storyId, formId, length, density): idempotent without a query |
| Book idempotency | Optional `idempotencyKey` → `bk_` + hash(ownerUid, key); a repeat returns the Book, uncharged. Without it every call is a new Book (and a new charge) |
| Allowance | Consumed in the creating transaction with the pure helpers of `src/lib/entitlements` (`consume`, `ensureFreeTier`); 402 `ENTITLEMENT_LIMIT` when none is left. Admin-created Books charge the story owner |
| Exact page count | The model is asked for exactly `length` pages; if it returns another count the pages are fitted (merge the shortest neighbours / split the longest at a sentence, else a word). Text shorter than `length` words fails `STORY_TOO_SHORT` |
| No chunking fallback | Today a failed pagination silently falls back to sentence chunking without scenes. Here the job fails and is retried; the Manuscript fails after its attempts |
| Scene fields | `Scene` adds `locationKey`, `mood`, `tag` (scene tag) and `castActions[]` to `location`, `presentCast`, `action`; the first description of a location is used for every page there (today's `locationRegistry`, no longer written to the story) |
| Cover | The pagination call also designs the cover scene (one call instead of today's separate cover-scene call); the hero is guaranteed on it; fallback is page 1's place. Stored as `Manuscript.cover`; `Manuscript.title` keeps the title for the cover text |
| Book pages | Page 1 cover, pages 2…length+1 story pages, created with the Book. Title, dedication, end and blank pages belong to a print Layout (print slice). The back cover is not drawn in this slice |
| Narration text | `ManuscriptPage.narrationText` keeps name pronunciations and `[audio directions]`; display `text` strips both. eleven_v3 gets `[British accent]` as today; other models get the directions stripped |
| Cast-sheet source | `portrait` (canonical) → `photos` (up to 3 originals, while a member has photos but no portrait yet) → `appearance` (text only). `CastSheet.source` gains `photos` |
| Page references | Per present member: its cast sheet, else portrait, else first photo; never the avatar |
| Failed cast sheet | Does not stop page art (the page falls back to the portrait/photo or words) |
| Prompt simplification | Attempt 1 full, attempt 2 without style images, attempt 3 text only (no images); a model refusal (no image, safety, pattern error) is retryable at job level so the simpler prompt gets its turn |
| Storage paths | `books/{bookId}/castSheets/{castId}/{jobId}-{attempt}.{ext}`, `books/{bookId}/pages/{n}/{jobId}-{attempt}.{ext}`, `manuscripts/{id}/narration/{n}/{jobId}-{attempt}.mp3`; no inline data-URL fallback |
| Lock / unlock | Lock from `ready` or `partial`; unlock returns to the status the art gives. `bookUnlockHooks` run inside the unlock transaction (reads, then writes) — where share-link revocation will register |
| Prompts from config | `systemConfig/paginationPrompt` and `systemConfig/imagePrompt` read through `ConfigService` (`paginationPromptConfig`, `imagePromptConfig`); the old loaders stay for `storybookV2` until 5.2 |
| Coordinator queue | `render` (cheap, no provider quota) |
| Foundation additions | `PaymentRequiredError` (402); `Repository.replaceIn` (create-or-replace in a transaction, for idempotent rewrites); `FanInContext.db` |
